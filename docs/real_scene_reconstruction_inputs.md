# 真实场景重建输入说明

本文说明使用 Real2Sim 系统重建一个真实机器人场景时需要准备的输入数据。

## 1. 视频

### 多视角 RGB 视频

建议使用多个固定相机同时拍摄：

```text
videos/
├── camera_00.mp4    # 主视角
├── camera_01.mp4    # 左侧或侧面视角
└── camera_02.mp4    # 顶部视角
```

要求：

- 保留原始分辨率和帧率
- 不裁剪、不变速、不重复压缩
- 相机尽量固定
- 各路视频需要时间同步
- 覆盖桌面、机器人和目标物体的主要区域

多视角的作用是减少遮挡，观察水瓶背面、夹爪内侧、桌面边缘和其它物体。

### RGB-D 视频

如果使用 RGB-D 相机，需要同时提供 RGB 图像和深度图：

```text
videos/
├── rgb_00.mp4
└── depth_00/
    ├── 000000.png
    ├── 000001.png
    └── ...
```

还需要提供深度值的缩放系数，例如 `depth_scale: 0.001`。RGB-D 可以直接帮助估计物体距离、桌面高度和三维位置。

## 2. 相机标定

每个相机需要内参和外参。

### 内参

内参描述相机如何把三维点投影到图像：

```json
{
  "width": 1920,
  "height": 1080,
  "fx": 935.3,
  "fy": 935.3,
  "cx": 960.0,
  "cy": 540.0,
  "distortion_model": "plumb_bob",
  "distortion": [0.01, -0.02, 0.0, 0.0, 0.0]
}
```

### 外参

外参描述相机相对于机器人基座或世界坐标系的位置：

```json
{
  "translation_m": [0.80, -1.20, 1.65],
  "rotation_quat_wxyz": [0.70, 0.0, 0.70, 0.0],
  "reference_frame": "robot_base"
}
```

如果没有标定文件，可以提供棋盘格或 AprilTag 标定板照片，并说明标定板的实际尺寸。

## 3. 精确机器人模型

需要提供真实机器人型号和模型文件，例如：

```text
robot/
├── robot.urdf
├── robot.xml
└── meshes/
```

至少需要包含：

- 机器人型号
- 每个关节的位置和旋转轴
- 关节名称和顺序
- 关节角度范围
- 连杆几何
- 机器人基座坐标系
- TCP 或末端执行器坐标系
- 夹爪几何

如果没有精确机器人模型，只能使用自由度和外观相似的机器人替代，不能保证真实轨迹和碰撞一致。

## 4. 机器人关节和夹爪日志

### 关节日志

推荐使用带时间戳的 CSV：

```csv
timestamp,joint_1,joint_2,joint_3,joint_4,joint_5,joint_6
0.000,0.12,1.03,1.42,-0.31,0.52,0.08
0.033,0.13,1.04,1.41,-0.30,0.52,0.08
```

### 夹爪日志

如果只有开合状态：

```csv
timestamp,state
0.000,open
2.740,closed
7.900,open
```

如果可以提供夹爪宽度，优先使用夹爪宽度：

```csv
timestamp,width_m
0.000,0.080
2.740,0.018
7.900,0.080
```

日志必须与视频使用相同时间基准。这样系统才能知道视频中的哪一帧对应哪个机器人状态，以及夹爪何时闭合。

## 5. 场景尺寸和尺度参考

需要提供场景的绝对尺寸，例如：

```json
{
  "table": {
    "length_m": 1.20,
    "width_m": 0.80,
    "height_m": 0.762
  },
  "workspace_origin": [0.0, 0.0, 0.0]
}
```

可以提供：

- 桌面长、宽和高度
- 墙面或柜体位置
- 机器人基座到桌面的距离
- 水瓶高度和直径
- 托盘、杯子和其它物体的尺寸

最推荐在场景中放置一个已知尺寸的 AprilTag，例如边长 10 cm。它可以帮助估计相机姿态和绝对尺度。

## 6. 物体清单

物体清单决定哪些物体需要进入仿真，以及每个物体需要多详细的模型。

示例：

```json
[
  {
    "name": "water_bottle",
    "category": "bottle",
    "dimensions_m": [0.066, 0.066, 0.240],
    "mass_kg": 0.55,
    "physics": true,
    "collision": true
  },
  {
    "name": "tray",
    "category": "tray",
    "dimensions_m": [0.35, 0.25, 0.04],
    "static": true,
    "collision": true
  },
  {
    "name": "paper_card",
    "category": "paper",
    "visual_only": true,
    "collision": false
  }
]
```

每个物体最好包含：

- 名称或类别
- 初始位置和姿态
- 是否需要视觉模型
- 是否需要碰撞
- 是否可移动
- 尺寸
- 质量
- 材质
- 摩擦特性

如果尺寸或质量未知，可以填写估计值，但报告中必须标记为假设。

## 7. 任务描述

任务描述最好同时包含自然语言指令和成功判据：

```json
{
  "instruction": "抓取桌面上的水瓶并抬离桌面",
  "target": "water_bottle",
  "gripper": "left",
  "success": {
    "min_lift_height_m": 0.08,
    "must_have_finger_contact": true,
    "max_penetration_m": 0.005
  }
}
```

建议明确：

- 目标物体
- 使用哪只手
- 起始状态
- 目标动作
- 结束状态
- 成功和失败条件
- 是否允许碰倒其它物体

例如：

```text
左夹爪接近水瓶，夹爪闭合，水瓶离开桌面至少 8 cm，保持 1 秒，且不碰倒杯子和托盘。
```

## 9. 最低配置与推荐配置

### 最低配置

```text
单个 MP4
+ 任务描述
+ 一个已知尺寸参考
```

结果只能是近似仿真，机器人、相机、物体尺寸和轨迹可能是估计值。

### 推荐配置

```text
多视角或 RGB-D 视频
+ 相机内外参
+ 精确机器人模型
+ 关节和夹爪日志
+ 场景尺寸
+ 物体清单
+ 任务描述
```

这套配置才适合进行较真实的场景重建、真实轨迹复现和可验证的数字孪生构建。

## 10. 能力边界

单目 MP4 无法唯一确定：

- 被遮挡区域的几何
- 物体的绝对尺寸
- 物体质量和摩擦系数
- 真实机器人型号
- 真实关节轨迹

因此，只有 MP4 时，系统输出应称为“基于假设的任务仿真”；加入相机标定、机器人状态和尺度参考后，才能逐步提高到“可验证的数字孪生”。
